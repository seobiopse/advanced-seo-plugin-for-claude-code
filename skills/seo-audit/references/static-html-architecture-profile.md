# Static HTML / Jamstack Architecture Profile

Site-level audit patterns for statically generated sites — Eleventy (11ty), Jekyll, Hugo, Astro (non-React), plain HTML/CSS, and any Jamstack site where HTML files are pre-built and served directly from a CDN.

**Key advantage:** static sites are naturally crawler-friendly. Every page is a real HTML file. No JS execution needed to see content. The SEO issues here are structural and build-process related, not rendering issues.

## 1. When to read this

Load this file when:
- The site is generated by Eleventy, Jekyll, Hugo, Astro, Gatsby (with static output), or similar SSG.
- The deployment is to Netlify, Vercel (static), Cloudflare Pages, GitHub Pages, or an S3/CDN bucket.
- Source is `.html` files without a server-side language executing per request.
- There is no `wp-config.php`, `app.py`, `routes.rb`, `pom.xml`, or equivalent backend framework marker.

## 2. Build-time SEO opportunities

Static sites process every page at build time. This is actually a superpower for SEO — run checks during the build that prevent SEO regressions from ever reaching production.

### SEO validation at build time

Tools you can integrate into CI/CD:

```bash
# Lighthouse CI (runs Lighthouse on every PR)
npm install -g @lhci/cli
lhci autorun --collect.url=https://staging.example.com/ --assert.preset=lighthouse:recommended

# HTML validator
npx html-validate dist/**/*.html

# Broken link checker
npx broken-link-checker https://staging.example.com/ --recursive

# Schema validator
curl -s https://staging.example.com/ | node check-schema.js
```

### Build output structure

Every route should map to a clean HTML file:

```
dist/
├── index.html              → /
├── about/index.html        → /about/
├── blog/index.html         → /blog/
├── blog/post-slug/index.html → /blog/post-slug/
└── sitemap.xml
```

The `index.html` pattern produces URLs without `.html` extensions. Never use `/about.html` as a live URL — it looks dated and creates trailing-slash inconsistency.

### Trailing slash consistency

Pick one and enforce at build time:
- With trailing slash: `/about/` (served via `/about/index.html`) — preferred
- Without trailing slash: `/about` (served via `/about.html`) — works but riskier

Inconsistency (some pages with slash, some without) creates duplicate content. Configure your CDN/hosting to redirect the non-canonical form:

**Netlify (`netlify.toml`):**
```toml
[[redirects]]
  from = "/about"
  to = "/about/"
  status = 301
```

**Cloudflare Pages / Vercel:** enable "Trailing Slash Normalization" in settings.

## 3. Template-level meta and schema injection

In static sites, SEO tags are injected at template level. Every page type should have a base template that handles metadata correctly.

### Eleventy example (`base.njk`)

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>{{ title | default(site.title) }} | {{ site.name }}</title>
  <meta name="description" content="{{ description | default(site.description) | truncate(160) }}">
  <link rel="canonical" href="{{ site.url }}{{ page.url }}">
  <meta property="og:title" content="{{ title | default(site.title) }}">
  <meta property="og:description" content="{{ description | default(site.description) | truncate(200) }}">
  <meta property="og:url" content="{{ site.url }}{{ page.url }}">
  <meta property="og:image" content="{{ ogImage | default(site.ogImage) }}">
  <meta property="og:type" content="{{ ogType | default('website') }}">
  {% if schema %}
  <script type="application/ld+json">{{ schema | dump | safe }}</script>
  {% endif %}
</head>
```

### Hugo example (`baseof.html`)

```html
<head>
  <title>{{ .Title }} | {{ .Site.Title }}</title>
  <meta name="description" content="{{ .Description | default .Site.Params.description }}">
  <link rel="canonical" href="{{ .Permalink }}">
  {{ template "_internal/opengraph.html" . }}
  {{ template "_internal/schema.html" . }}
  {{ template "_internal/twitter_cards.html" . }}
</head>
```

Hugo has built-in internal templates for OpenGraph and schema — use them and extend, don't reinvent.

### Jekyll example (`default.html`)

```html
<head>
  <title>{{ page.title | default: site.title }}</title>
  <meta name="description" content="{{ page.description | default: site.description | truncate: 160 }}">
  <link rel="canonical" href="{{ page.url | prepend: site.url }}">
  {% if page.schema %}
  <script type="application/ld+json">{{ page.schema | jsonify }}</script>
  {% endif %}
</head>
```

### Schema injection pattern

For static sites, schema is best defined in the page's front matter and injected via the template:

```yaml
# content/blog/post-title.md front matter
---
title: "Post title"
description: "Meta description"
date: 2026-04-18
schema:
  "@type": "Article"
  "headline": "Post title"
  "datePublished": "2026-04-18"
  "author":
    "@type": "Person"
    "name": "Girish Kumar G"
---
```

## 4. Sitemap generation

Static site generators produce sitemaps at build time. Each major SSG has a plugin/built-in approach.

### Eleventy

Use `@quasibit/eleventy-plugin-sitemap`:

```js
// .eleventy.js
const sitemap = require("@quasibit/eleventy-plugin-sitemap");
module.exports = function(eleventyConfig) {
  eleventyConfig.addPlugin(sitemap, {
    sitemap: {
      hostname: "https://example.com",
      lastModifiedProperty: "modified",
      excludeURLs: ["/404/", "/drafts/"],
    },
  });
};
```

### Hugo

Built-in sitemap at `/sitemap.xml`. Configure in `config.toml`:

```toml
[sitemap]
  changefreq = "monthly"
  filename = "sitemap.xml"
  priority = 0.5
```

Override per-page with front matter:
```yaml
sitemap:
  priority: 0.8
  changefreq: weekly
```

### Jekyll

Use `jekyll-sitemap` gem:

```yaml
# _config.yml
plugins:
  - jekyll-sitemap
url: "https://example.com"
```

Excludes pages with `sitemap: false` in front matter.

### Common sitemap issues on static sites

- **`<lastmod>` set to build date** — every URL gets today's date, defeating the freshness signal. Use the actual file's git commit date or front-matter date.
- **Draft/test pages included** — exclude with `published: false` or similar.
- **All priorities identical** (`0.5`) — fine to omit, but if set, vary them meaningfully.

### Getting real lastmod from Git

For Hugo:
```toml
# config.toml
[frontmatter]
  lastmod = [":git", "lastmod", ":fileModTime"]
```

For Eleventy (custom):
```js
const { execSync } = require('child_process');
module.exports = function(data) {
  const gitDate = execSync(`git log -1 --format="%ci" -- ${data.page.inputPath}`).toString().trim();
  return gitDate || data.date;
};
```

## 5. robots.txt at build time

Static sites serve a physical `robots.txt` file. This is actually simpler and more reliable than dynamic generation.

### Recommended robots.txt for a static site

```
User-agent: *
Allow: /

# AI retrieval crawlers — allow for GEO
User-agent: ChatGPT-User
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: ClaudeBot
Allow: /

# Training crawlers — business decision
User-agent: GPTBot
Allow: /

User-agent: CCBot
Allow: /

Sitemap: https://example.com/sitemap.xml
```

### Preventing staging indexation

For Netlify/Vercel preview deployments, add an `X-Robots-Tag: noindex` response header for non-production environments rather than a different `robots.txt`. The same `robots.txt` gets deployed to all environments.

**Netlify (`netlify.toml`):**
```toml
[[headers]]
  for = "/*"
  [headers.values]
    X-Robots-Tag = "noindex, nofollow"
# Only set this in a branch-specific config, not in main
```

## 6. Hosting and CDN SEO considerations

Static sites run on CDNs/edge networks. The hosting layer has SEO-relevant settings.

### Cache-Control headers

Static assets should be cached aggressively; HTML should have shorter TTLs to allow updates to propagate:

**Netlify (`netlify.toml`):**
```toml
[[headers]]
  for = "/*.html"
  [headers.values]
    Cache-Control = "public, max-age=0, must-revalidate"

[[headers]]
  for = "/assets/*"
  [headers.values]
    Cache-Control = "public, max-age=31536000, immutable"
```

### HTTPS enforced

All static hosting providers support HTTPS by default. Verify:
- The CDN forces HTTP → HTTPS redirect (not just serving both).
- `www` → non-www (or vice versa) redirect is configured.
- HSTS header is set: `Strict-Transport-Security: max-age=31536000`.

### Custom 404 page

A well-configured 404 page is important for crawl health. It must return HTTP 404 (not 200):

**Netlify:** Create `404.html` at the root of your `dist/` folder.
**GitHub Pages:** Create `404.html` at the repo root.
**Cloudflare Pages:** Same as Netlify.

Check: `curl -sI https://example.com/this-does-not-exist | head -1` — should return `HTTP/2 404`.

## 7. 404s and redirects

Static sites change URLs less frequently, but when they do, 301 redirects are handled at the hosting/CDN layer.

### Netlify redirects

```toml
# netlify.toml
[[redirects]]
  from = "/old-post-title/"
  to = "/new-post-title/"
  status = 301

[[redirects]]
  from = "/blog/*"
  to = "/articles/:splat"
  status = 301
```

Or in a `_redirects` file:
```
/old-post-title/    /new-post-title/    301
/blog/*             /articles/:splat    301
```

### Cloudflare Pages / Vercel

Both support `_redirects` files or configuration-level redirect rules. Always use 301 (permanent) for URL migrations.

### Tracking broken URLs

Run a broken-link audit before and after any URL structure change:

```bash
npx broken-link-checker https://example.com --recursive --ordered --exclude "mailto:" --exclude "tel:"
```

## 8. Image optimization at build time

The biggest performance opportunity on static sites is build-time image processing.

### Eleventy Image plugin

```js
const Image = require("@11ty/eleventy-img");
async function imageShortcode(src, alt, sizes = "100vw") {
  let metadata = await Image(src, {
    widths: [400, 800, 1200],
    formats: ["avif", "webp", "jpeg"],
    outputDir: "./dist/img/",
    urlPath: "/img/",
  });
  let imageAttributes = {
    alt,
    sizes,
    loading: "lazy",
    decoding: "async",
  };
  return Image.generateHTML(metadata, imageAttributes);
}
```

### Hugo image processing

```html
{{ $image := resources.Get "img/hero.jpg" }}
{{ $webp := $image.Resize "1200x webp" }}
{{ $jpg := $image.Resize "1200x jpeg" }}
<picture>
  <source srcset="{{ $webp.RelPermalink }}" type="image/webp">
  <img src="{{ $jpg.RelPermalink }}" alt="{{ .Params.heroAlt }}"
       width="{{ $jpg.Width }}" height="{{ $jpg.Height }}"
       loading="eager" fetchpriority="high">
</picture>
```

### LCP image — never lazy-load

The hero/above-fold image MUST have `loading="eager"` (or omit `loading` attribute). Build-time image processing often adds `loading="lazy"` universally — override for the first image in each template.

## 9. Common anti-patterns

### 9.1 `.html` extension in URLs
`/about.html` instead of `/about/`. Dates the site, creates trailing-slash inconsistency, harder to migrate later. Use the `index.html` pattern for clean URLs.

### 9.2 Hardcoded production URLs in templates
`<link rel="canonical" href="https://example.com/about/">` hardcoded instead of using a site variable. Breaks staging previews — every staging page canonicalises to production.

### 9.3 Missing `<html lang="">` attribute
A trivial fix that affects language detection by crawlers and assistive technology.

### 9.4 Build-level sitemap always showing today's date
Most SSG plugins default `<lastmod>` to the build date. This teaches Googlebot to ignore your `<lastmod>` signals entirely. Use git dates or front-matter dates.

### 9.5 No redirect file for URL changes
Developers update a post's slug without adding a redirect entry. The old URL starts 404ing, losing any link equity and breaking external links.

### 9.6 Giant unprocessed images committed to the repo
`/images/hero.png` at 4MB committed to the Git repo, served directly to users. Use the SSG's image processing pipeline or an image CDN (Cloudinary, imgix).

### 9.7 No OG image or generic fallback
Static sites often have a global OG image (`og:image`) hardcoded in the base template. Every page shares the same image, which looks unprofessional in social previews. Generate per-page OG images or at minimum vary them by section.

## 10. Audit checklist

- **SH-1** URLs use clean paths without `.html` extension. `/about/` not `/about.html`. Check: `curl -sI https://example.com/about.html` should return 301 → `/about/`.
- **SH-2** Trailing slash consistent across all pages. Pick one convention; redirect the other.
- **SH-3** `<html lang="xx">` present on all pages. Check: `curl -s https://example.com/ | grep "<html"`.
- **SH-4** `<title>`, `<meta name="description">`, and `<link rel="canonical">` present on every page and populated with page-specific values (not defaults on all pages).
- **SH-5** Canonical URL uses site variable, not hardcoded production URL. Verify on staging: canonical should point to staging URL, not `https://example.com/`.
- **SH-6** OpenGraph tags complete: `og:title`, `og:description`, `og:url`, `og:image` (≥ 1200×630 absolute URL).
- **SH-7** Schema present on appropriate page types: `Organization`/`WebSite` on homepage; `Article` on posts; `BreadcrumbList` on deep pages.
- **SH-8** Sitemap at `/sitemap.xml` returns HTTP 200. All URLs return HTTP 200 (spot-check 10).
- **SH-9** `<lastmod>` in sitemap reflects actual content change date, not build date. Spot-check: compare `<lastmod>` to the git commit date or front-matter date for 3 pages.
- **SH-10** `robots.txt` at `/robots.txt` HTTP 200. Contains `Sitemap:` directive. Does not contain `Disallow: /` on production.
- **SH-11** HTTPS enforced. HTTP → HTTPS 301 redirect working. `curl -sIL http://example.com/` returns `301 → https://`.
- **SH-12** `Strict-Transport-Security` header present. `curl -sI https://example.com/ | grep -i hsts`.
- **SH-13** Custom 404 page returns HTTP 404 (not 200). `curl -sI https://example.com/nonexistent-page | head -1`.
- **SH-14** Hero / LCP image NOT lazy-loaded. Check: first `<img>` in the body has no `loading="lazy"` or has `loading="eager"`.
- **SH-15** Images served in WebP/AVIF format. Check: `curl -sI https://example.com/img/hero.jpg -H "Accept: image/webp"` → `Content-Type: image/webp`.
- **SH-16** `width` and `height` attributes present on all `<img>` tags (prevents CLS).
- **SH-17** No broken internal links. Run: `npx broken-link-checker https://example.com --recursive`.
- **SH-18** Redirect file (`_redirects`, `netlify.toml`, or equivalent) in place for all changed URLs. No 404 spikes in GSC after recent deploy.
- **SH-19** Staging deployment returns `X-Robots-Tag: noindex` response header (not a `robots.txt` with `Disallow: /`).
- **SH-20** Build-time image processing active — no full-resolution original images served in `<img>` tags.
